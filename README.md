# knet-replay-site
> [!CAUTION]
> 本ツールは防災科学技術研究所（NIED）の強震データ（K-NET/KiK-net等）を[MeteoQuake-KyoshinViewer](https://github.com/skotm/MeteoQuake-KyoshinViewer) のリプレイファイルのフォーマットに変換するためのものです。データの利用にあたってはNIEDの利用規約に従い、データの二次配布は行わないでください。また、成果物公開時はDOIを明記してください。

## 使い方(サイト側)
1. K-NET ASCIIファイル(1観測点につきNS/EW/UD3つ)をドラッグ&ドロップまたは選択
2. 「変換開始」→ ログに進捗が表示される
3. 完了後、ファイル名を確認(発生時刻+マグニチュードから自動生成される)して
   ダウンロード
4. MeteoQuake本体の「設定→詳細設定→リプレイ」からそのまま読み込める

## デプロイ方法
このディレクトリの中身をそのままGitHub Pagesのリポジトリルートに置くだけ。
```
index.html
app.js
jmaIntensity.js
knetAsciiParser.js
protocolEncode.js
kmoniObsPoints.js
intensity-points.json
```
ビルドステップは無い(ESモジュールとして`<script type="module">`で読み込んでいる)。

## 大きなzip・大規模地震(数百観測点)への対応
345MB級のzip(2011年東北地方太平洋沖地震のような数百観測点規模)でも
処理落ちしないよう、以下の設計にしている:
- **即時ディスパッチ方式**: 全観測点のデータを読み終えるまで待たず、
  ある観測点の3成分(NS/EW/UD)が揃った瞬間にWorkerへ処理を投げ、
  メモリからは即座に削除する。全観測点のデータを同時にメモリへ
  保持することが無い(以前の設計はここがボトルネックだった)
- **Float64Array(typed array)化**: 生の加速度データをFloat64Arrayで
  保持することで、メモリ効率を向上
- **Transferable postMessage**: WorkerへのデータはFloat64Arrayの
  ArrayBufferを「転送」(構造化クローンでのコピーではなくゼロコピー
  移動)する。メインスレッド↔Worker間のコピーコストを削減
- 明らかに無関係なファイル(.txt/.ch/.pdf)は展開前に名前で除外
- 重い計算(FFTフィルタ)はWeb Worker上で実行(最大4並列)
- 定期的にイベントループへ制御を返し、進捗ログ・プログレスバーが
  更新され続けるようにしている

WorkerPoolのキュー管理・ストリーミングディスパッチ(3成分が揃った瞬間だけ
処理される、未完了の観測点は残る)のロジックは単体テスト済み。
Float64Array化後も震度計算結果が変わらないこと(気象庁フィルタ・2012フィルタ
双方)を実データで回帰確認済み。

## フィルタの選択(2種類)
- **気象庁フィルタ(FFTベース厳密)**: 気象庁公式の計測震度算出方法をそのまま
  実装したもの。オフラインでの精密計算向け
- **2012フィルタ(強震モニタ相当)**: 功刀・他(2013)「震度のリアルタイム演算
  に用いられる近似フィルタの改良」(地震 第2輯 第65巻, DOI: 10.4294/zisin.65.223)
  で提案された、時間領域の逐次IIRフィルタ(2次×6段+ゲイン)。これは
  **防災科学技術研究所のK-NET・KiK-net強震計に実際に組み込まれ、
  「強震モニタ」の表示に使われている方式**(論文内に明記)。気象庁フィルタと
  完全一致はしないが、震度4以上のデータで99%が誤差0.1以内に収まると論文で
  報告されている

強震モニタ(kmoni)の表示値に近づけたい場合は2012フィルタを、気象庁の厳密な
算出方法をそのまま使いたい場合は気象庁フィルタを選択する。

### 2012フィルタの検証
- 周波数特性を実測し、論文Fig.3の記載(0.1〜50Hzで気象庁フィルタとの差異が
  0.974〜1.029倍)と一致することを確認(0.1〜50Hzの10点で検証、いずれも
  比率0.99〜1.03程度)
- 論文のOCR化テキストにβ0/β2式で"ωa2"という表記があったが、文脈上
  "ωa3"の誤記と判断して読み替えている(この読み替えが正しいことは
  上記の周波数特性検証で裏付けている)
- 実データ(FKOH01)で気象庁フィルタとの震度差を確認(-0.08程度)。これは
  この記録が震度-1.5程度とほぼノイズレベルであるための誤差拡大と考えられ、
  論文が主に検証した震度4以上の記録とは条件が異なる点に留意

## 検証したこと
- `knet-replay`(Node版)で検証済みのロジックを移植し、同じテストケース
  (気象庁公式実例、FFTフィルタ理論値、K-NET FAQ実例、protocolエンコード/diff)
  を移植後のコードに対して再実行し、全て一致することを確認
- kmoni観測点へのID割当が、実際のリアルタイム配信サーバー側の割当
  (`ABSH01`→id=1、総数1,628件)と完全に一致することを確認
- 方向表記("N-S"/"E-W"/"U-D"、ハイフン無し等)の正規化ロジック
- ファイル名自動生成ロジック(JST日付をまたぐケース含む)
- **実際にNIEDからダウンロードしたzip(K-NET・KiK-net混在)で動作確認**:
  - KiK-netは`Dir.`欄が"N-S"等の文字列ではなく数値コード(1〜6、表層/地中の
    区別込み)であることを実データで確認し、対応を追加
  - 生の加速度データには観測点固有の大きな直流バイアス(基線)が乗っており、
    そのままFFTフィルタにかけるとゼロパディング境界の不連続からフィルタ後に
    異常な巨大値が出る不具合を実データで発見・修正(基線補正を追加)

## 対応データ形式
- K-NET ASCII(表層のみ、`Dir.`は"N-S"/"E-W"/"U-D"形式)
- KiK-net ASCII(表層+地中ペア、`Dir.`は数値コード1〜6形式)。**地中(borehole)
  側は現状使用せず、表層側のみを震度計算に使う**(kmoniの実際の震度表示との
  整合を優先)
- NIEDダウンロード時のzipファイルをそのまま読み込み可能(自動展開)

## 依存
- `fft.js`をCDN(jsdelivr)からESモジュールとしてimportしている
  (`jmaIntensity.js`内)。オフラインでは動作しない

## 既知の制約
`knet-replay`(Node CLI版)と同様:
- 観測点コードがMeteoQuakeの既知観測点リストに無い場合はスキップされる
  (S-net観測点のK-NETデータには非対応)
- ウィンドウ幅・ステップは気象庁の公式仕様ではなく、リプレイアニメーション
  用の独自近似パラメータ
- 大量データはブラウザのメモリ・処理能力に依存する(タブが固まる可能性が
  あるため、あまりに多い観測点・長時間の波形は分割して処理することを推奨)
